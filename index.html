About Continuous Integration

Continuous Integration is a software development practice in which developers regularly add their code changes to a shared repository. Automated checks can then be performed to help identify errors early in the development process.

Instead of checking every project file manually, a developer can configure a workflow to run automatically when new code is pushed.

In this project, GitHub Actions is used to demonstrate a basic automated check for the existence of the website's HTML file.

What Is GitHub Actions?

GitHub Actions is an automation platform available on GitHub. It allows developers to create workflows that perform tasks in response to events in a repository.

These tasks may include checking files, running tests, building applications, and preparing software for deployment.

How It Works

  • A developer creates or updates a project file.
  • The changes are committed using Git.
  • The developer pushes the changes to GitHub.
  • GitHub Actions detects the configured event.
  • The workflow starts an automated job.
  • The job performs the checks defined in the workflow configuration.
  • GitHub displays the workflow result in the Actions section of the repository.

Introduction to TypeScript

TypeScript allows developers to specify the expected type of a variable, function parameter, or return value.

For example, a variable that is intended to store a person's name can be declared with the string type. 

// Example TypeScript code

let studentName: string = "Cloud Computing Student";

let projectWeek: number = 8;

function displayProject(name: string): string {
    return "Welcome to " + name;
}

console.log(displayProject(studentName));
console.log(projectWeek);

In this example, studentName stores text, while projectWeek stores a number. The function accepts a string and returns a string value.

TypeScript code is normally compiled into JavaScript before it runs in a browser or compatible JavaScript environment.

Basic CI Workflow

A GitHub Actions workflow is written in a YAML configuration file and stored inside the repository's .github/workflows directory.

The workflow can be configured to run whenever changes are pushed to the main branch. Its job can then check whether the index.html file exists. 

name: CI

on:
  push:
    branches:
      - main

jobs:
  test:
    runs-on: ubuntu-latest

    steps:
      - name: Checkout repository
        uses: actions/checkout@v4

      - name: Check website files
        run: |
          test -f index.html
          echo "index.html exists"
          echo "CI check completed successfully"

The workflow first checks out the repository files. It then uses a simple file check to determine whether index.html exists.

If the required file is missing, the check fails. If the file exists, the command completes successfully.

Benefits of Continuous Integration

  • Early error detection: Automated checks can help identify problems shortly after code changes are pushed.
  • Reduced manual work: Repeated checks can be performed automatically.
  • Consistency: The same workflow steps can run each time the configured event occurs.
  • Improved collaboration: Team members can view workflow results associated with repository changes.
  • Better development practices: Developers can gradually add more checks as their projects become more complex.
